Hybrid Training v36.102 — Deployment Resilience Hotfix QA/QC

ROOT CAUSE CONFIRMED
- Live GitHub repo was a mixed deployment: service worker at 36.101 while version.json and manifest remained at 36.100, and the new modular shell assets were not present.
- v36.101 treated any deployed-version mismatch as an update and could fall back to a forced reload before the page finished hydrating on a slower installed-PWA boot.

HOTFIX
- Update detection is now monotonic: only a strictly newer deployed build is considered an update.
- Older/stale version.json values are treated as deployment lag and never trigger reload.
- Forced location.replace fallback was removed from deployed-build detection.
- If the modular shell is unavailable, the core app keeps running and any truly newer update notice is deferred.
- Shell assets renamed to app-shell-v36.102.js/css to avoid stale-cache ambiguity.
